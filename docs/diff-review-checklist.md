# Чек-лист рев'ю дифу

> Принцип: читай кожен рядок, який згенерував агент. Відхиляй те, що не проходить. Краще відкотити, ніж влити сумнівне. (Конвенція проєкту — застосовуй на кожному PR/дифі.)

## Скоуп і розмір
- [ ] Зміни в межах задачі/специфікації; нема «заодно переписав півпроєкту».
- [ ] Діф читабельний за один прохід; якщо ні — розбити на менші.
- [ ] Не перевищує контекстний бюджет (нема дублювання, мертвого коду, зайвих абстракцій).

## Залежності
- [ ] Нових залежностей мінімум; кожна виправдана (на стадії прототипу — **нуль** npm-залежностей у рантаймі).
- [ ] Версії узгоджені; нема конфліктів чи непотрібних мажор-апгрейдів.
- [ ] Ліцензії сумісні.

## Security smell test
- [ ] Жодних секретів/ключів/токенів у коді чи логах.
- [ ] Вхідні дані валідуються; нема очевидних ін'єкцій.
- [ ] Зовнішні виклики йдуть на очікувані ендпоінти (Overpass), не на підставлені з контенту.

## Коректність і конвенції
- [ ] Відповідає AGENTS.md: неймспейс `RW`, порядок підключення скриптів, no-build, DOM-free логіка симуляції.
- [ ] Є тести під нову поведінку / критерії прийняття; `npm test` зелений.
- [ ] Обробка крайніх випадків, не лише «happy path».
- [ ] Нема закоментованого сміття, TODO без власника, debug-виводу.

## Рішення
- [ ] **Approve** — усе вище ✓.
- [ ] **Request changes** — конкретний список.
- [ ] **Reject / rollback** — порушує security/архітектуру або не в скоупі.
