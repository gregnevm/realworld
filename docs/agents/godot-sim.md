# Godot-порт: сим, кернел, мережа, persistence

> Деталі шарів живого сима. Виділено з `AGENTS.md` (OD-8, F6). Тримай актуальним разом із кодом.

- **Шари:**
  - `godot/scripts/` — `sim.gd` (детермінований сим: **фасад + стан + core loop**; публічний API незмінний — делегати), `session.gd` (оркестрація регіонів/подорожей/респавну), `social.gd`, `persistence.gd`, `world_gen.gd`, `world_view.gd` (custom-draw тайлмапи; роботи малюються окремо від рейдерів), `main.gd` (СТАРИЙ HUD-моноліт — заморожений референс, більше НЕ дефолтна сцена; виключений із gdlint).
  - `godot/scripts/sim/` — **доменні модулі живого сима** (декомпозиція моноліту): `threats.gd` (рейди кланів + **патрульні роботи** — лор постапокаліпсису, амбієнтний канал із seeded `threat_rng`, роботи = джерело брухту/компонентів; вороги/турелі/смерть/респавн), `environment.gd` (seed погодних/threat-стрімів, reroll погоди, indoor-BFS; дрібні гетери temp_at/light_at лишились публічним API sim.gd), `world_meta.gd` (капсули/інвайти spec 0002 + конвої). Патерн: **static func module(s, ...)** — модуль без стану, без preload sim.gd (без циклу); sim.gd тримає однорядкові делегати, тож session/тести/main.gd бачать той самий API.
  - `godot/scripts/kernel/` — **механічний кернел (spec 0003)**: `Def`/`Thing`+`ThingComp`/`StatWorker`+`StatPart`/`SimSystem`+`SystemRegistry`/`Balance`. «Додати механіку ніколи не редагує tick-loop».
  - `godot/content/catalog.json` + `godot/scripts/kernel/catalog.gd` — **дерево контенту** (повне: 335 def — ресурси/дослідження/будівлі/рецепти/предмети, від неоліту до космічного корабля) через seam `Defs.load_pack`. Чисті дані, RimWorld-канон + Factorio-ланцюги (довідник канону з формулами й числами — `docs/rimworld-reference.md`; перед тим як вигадувати механіку, дивись туди). Валідатор перевіряє ациклічність tech-DAG + **досяжність від сирих ресурсів** (нічого не «застрягло»). НЕ чіпає `data.gd`. Довідник — `docs/catalog.md`. Тести: `tests/catalog.test.js` (Node) + `godot/tests/run_catalog_tests.gd` (Godot).
  - **Research-ворота живого контенту (spec 0007 phase 2):** `data.gd` BUILDINGS/ITEMS несуть опційне `research: "<catalog-id>"`; `sim.research_unlocked` (мапа) живиться з `progression.research.unlocked` у `session.tick_research()`; `sim.try_build`/`craft_item` відмовляють до відкриття (🔒 + назва з `RESEARCH_LABEL`).   - **Відкритий склад (spec 0008 phase 2):** `sim.use_catalog` (дефолт OFF — шліфований зріз байт-у-байт; ставиться ДО `new_game`, не фліпається посеред сейва).   - **Живі каталожні build/craft + курований тір (spec 0008 phases 3–4, §5 підписано 2026-07-29):** другий шов — `sim.building_def(kind)`: data.gd першим (його 13 тюнених дефів виграють — одна правда на id), далі адаптер `catalog_defs.gd` для catalogue-only ids при прапорі ON; ВСІ tick-шляхи (blocks/enclosure/heat/light/traps/turrets/capacity/hp/refund/рендер world_view) читають шов. Живий build їде ІСНУЮЧОЮ граматикою: рядок браузера армить звичайний `select_build`-привид (у `catalog_verbs` через **WeakRef на роутер** — замикання з `ic` було б Callable↔контролер циклом), клік мапою падає в `try_build`, який говорить каталожними id крізь шов. Phase 4: видобуток при ON віддає ПАКЕТ ноди (скеля: руда/вугілля/глина/пісок упереміш із каменем; дерево: волокно; кущ: трави) — чиста функція `(cell, amount)` у `catalog_defs.gd`, нуль RNG-споживання (детермінізм потоків не зсувається), worldgen неторканий (голдени цілі). Живий тір ВИВЕДЕНИЙ, не хардкоджений: замикання досяжності від живих сировин = 38 ресурсів/73 будівлі/27 рецептів (неоліт→сталь/компоненти), закріплено дзеркально в `_t_catalog_live` (run_tests) і `catalog.test.js` (Node). HUD: браузери B/C/N фліпають бейдж «демо»→«живе» за `live`-прапором слайса, `build_actions` фільтровані до live-buildable, StockPanel — пул каталожних рядків. Дефолт лишається OFF: фліп на ON для нових ігор — окремий свідомий крок (§5.2 спеки).
  - **Жива енергомережа (Batch 8c, 2026-07-29):** `sim/power.gd` — міст dict↔Thing на кернел-орган `kernel/power.gd` (CompPowerSource/Trader/Battery + PowerNetSystem з пріоритетним brownout-шедінгом). Кернел-компи — авторитет фізики (пальне, кламп батарей, порядок скидання); дикти будівель — персистентна правда: `b.fuel`/`b.charge` дзеркаляться щотіка і їдуть у `serialize_region`/`world_hash`/rejoin (Thing-и ніколи не серіалізуються, флот перебудовується ліниво по `power_dirty`). Мережі ПРОСТОРОВІ: учасники групуються 4-суміжністю, `power_conduit` — пасивна ланка, що тягне мережу на відстань (BFS-компоненти в rebuild; кожна мережа солвиться окремо, HUD читає агрегат) — генератор живить те, чого торкається або куди дотягнуто кабель. Соляр читає РЕАЛЬНУ криву світла (`daylight_level`), вітер — seeded погодний потік (`WIND_FACTOR`), генератори авторефуеляться зі складу крізь stock-шов (1 юніт ресурсу = 1 паливо; мапа `GENERATOR_FUEL` у catalog_defs). `sim.device_active(b)` — шов Batch 8c як задумано: power-TRADER дефи живі лише з вердиктом мережі (турелі не стріляють, станції відмовляють `&"no_power"`), все інше (усі data.gd-дефи) — завжди. ГОЧА-ліфсайкл: Thing↔Comp цикли власні цьому модулю — rebuild детачить старий флот, тести звуть `sim.dispose_power()` перед скиданням сима (інакше ObjectDB-leak-гейт CI). HUD: `power`-слайс + `PowerPanel` (RIGHT, hotkey E). Тест — `_t_power_live` (run_tests): шедінг за пріоритетом, батарея-буфер, соляр день/ніч, авторефуел, персистенс fuel/charge, twin-хеші.

  - **Живий Balance-директор (2026-07-29):** `sim/director.gd` — `kernel/balance.gd` нарешті ПАСИТЬ гру, не лише HUD: `Balance.tick()` щотіка на ВЛАСНОМУ seeded потоці (`director_rng`, сіл у env_init поруч із погодним/threat; курсор — у runtime-записі → rejoin/twin-точність).   - **Локалізоване здоров'я героя + клімат із зубами (2026-07-29):** `sim/hero_health.gd` — доменний модуль живого сима (патерн threats/environment), що підключає кернел-субстрат до пішака: трекер `kernel/health.gd` на `sim.health` — ЄДИНА правда про тіло (`player.hp` — похідний редаут «відстань до найближчого канала смерті»). Удари ворогів лягають ранами на частини тіла (частина — з `threat_rng`, детерміновано; броня ріже до того), рани кровлять/інфікуються/гояться, сон у **ліжку** обробляє їх (bed-tend), тяжкі загоєні лишають шрами; capacity-канали живлять сим: швидкість руху (Moving), час роботи (Manipulation × Consciousness), сила удару. Смерть — за причиною, з фідом. Персистенс: `serialize_region.health` (сейв/`world_hash`/rejoin), капсула несе трекер у pawn, легасі-сейви мігрують hp-флоат у доглянуту рану тулуба; рестор ДОСЛІВНИЙ (hp не перераховується — біт-стабільність round-trip). ГОЧА кернела, яку викрила інтеграція: епсилонний `gone()` (0.02) вимітав щойно народжений кондиційний hediff на кадровому dday (~0.003/тік) — тепер точний нуль + fine-dday регресії в кернел-сьюті. Корпус заборони = `godot/scripts/` мінус `clock.gd`, `ui/**`, `world_view.gd`, `map_widget.gd`, `main.gd`, `newhud_main.gd` (там `Time.get_ticks_msec` крутить пульс/трясіння камери — view, не sim-час); НОВИЙ скрипт покритий за замовчуванням. Два примусові боки одного списку: `npm run lint` (`tools/process/lib.mjs`: `SIM_CORPUS_EXCLUDE`/`SIM_CLOCK_BAN`) і `run_tests.gd::_t_no_wallclock_in_sim` (`SIM_CORPUS_EXCLUDE`/`SIM_CLOCK_PATTERNS`); `tests/process.test.js` звіряє їх. Хибнопозитив — коментар `# clock-ok` (виклик годинника/RNG) або `# rng-ok` (RNG, засіяний там, де лінт не бачить). Споживач у `Session` (`pump_clock`/`now_ms`) і `Sim.set_clock` — наступні хвилі spec 0012; `clock.gd` сам нікого не підключає і `world_hash` не міняє.
