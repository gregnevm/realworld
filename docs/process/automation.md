# Автоматизація та інструментарій

> Найцінніший автомат — не генерація коду, а цикл **«запустити → побачити → виправити»** з доказом (Luden.io: агенти найкращі там, де гра віддає стан текстом і детерміновано). Тут: драбина доказів, що вже стоїть у CI, радар інструментів і LLM Week.

## 1. Драбина доказів

Кожен рівень ловить те, чого не бачить попередній. Новий агентний результат піднімається драбиною, доки не дійде до рівня, якого вимагає його ризик.

| # | Рівень | У цьому репо | Коли | Не бачить |
|---|---|---|---|---|
| 1 | Парсинг / імпорт | `godot.yml` scene parse check · `gdlint` · `npm run lint` (контракт веб-зрізу + **Godot-3 API tripwire**, F1) | кожна правка | рендер |
| 2 | Headless-запуск | `godot.yml` headless-сьюти з гейтом ObjectDB-ліків | кожна правка | інші GPU, кадр |
| 3 | Юніт/інтеграційні тести | `run_*.gd` (≈1000 перевірок) · `node --test` (сим-ядро, каталог, прогресія, арт, процес) | кожен PR | гру очима гравця |
| 4 | Детермінізм | `run_determinism_tests` twin-хеш + крос-процесний `WORLD_HASH_FINAL` · `run_rejoin_tests` | кожен PR | чи цікаво |
| 5 | Сценарні E2E | `tools/smoke.mjs` (Playwright, веб) · `run_smoke` · `run_net_spike` (сервер + 2 клієнти) | перед мерджем фічі | ламаються, коли гра змінюється |
| 6 | Кадр інтерфейсу | CI `godot-hud-screenshot` · `newhud shot [inv\|bag\|death\|spawn\|fx\|touch…]` · `tools/ux/value_check.py` · агент `fresh-eyes` | кожна видима зміна | feel (статичний кадр) |
| 7 | Експорт і доставка | CI `godot-web-build` (артефакт `web-build`) · `godot-android-build` (`android-apk`, `apksigner verify`) | кожен пуш | — |
| P | **Процес** | `process.yml`: PR-гейт + звіт здоров'я; SessionStart-дайджест (§5, вмикає власник) | кожен PR / сесія | якість рішень власника |

**Правила роботи з драбиною:**
- Агент бачить гру **кадром і текстом**, не уявою: для UI/колізій — кадр із debug-draw, для бага — seed + кроки + `world_hash` до/після (P5).
- Відтворюваний баг: людина записує його один раз (seed, дії); агент відтворює з тим самим seed і `--fixed-fps` до і після виправлення.
- Агент пише собі документацію про механіки (`docs/mechanics-status.md`, `docs/rimworld-reference.md`) — після цього він реалістичніше будує сценарії (Luden.io).
- **Версія рушія закріплена: Godot 4.7** (`AGENTS.md`, CI). «Godot 4» — не інструкція; лише точний номер (R1).

## 4. MCP і безпека агентів

- MCP-сервер діє **на машині власника**: коміт перед кожною сесією, лише довірені сервери, вимкнені зайві інструменти (R12).
- Один MCP-міст до редактора за раз. Більше інструментів ≠ більше продуктивності (R4).
- Секрети — лише `.env.local` / змінні середовища; `npm run lint` сканує ключі в усіх трекнутих файлах.
- Прототипи — в окремому git-worktree; одноразовий код не торкається основного дерева.

## 5. Сесійний хук (вмикає власник)

Агент не пам'ятає між сесіями, а після компактації контексту губить стан. Хук `SessionStart` вставляє в контекст дайджест процесу (`report.mjs --brief`: відкриті OD, scope, rework-вердикт, плейтест, попередження) — на старті й після компактації.

**Необов'язково:** без хука агент і так запускає дайджест на старті сесії й після компактації — це тригер у таблиці процесу в `AGENTS.md`. Хук лише робить це механічно, а не за інструкцією. Агент **не вмикає хуки сам** (зміна власного конфігу — рішення людини). Щоб увімкнути, власник додає в `.claude/settings.json` (проєкт, комітиться) або `.claude/settings.local.json` (лише себе):

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|compact",
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/tools/process/report.mjs\" --brief", "timeout": 20 }
        ]
      }
    ]
  }
}
```

Перевірка: `echo '{}' | node tools/process/report.mjs --brief` друкує ≤ 12 рядків і завжди виходить з кодом 0. Огляд/вимкнення — `/hooks`.

## 6. LLM Week
