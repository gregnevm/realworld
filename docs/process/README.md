# Процес розробки RealWorld

> Конституція: як ми робимо гру з ШІ-командою. Філософія → принципи → цикл → ролі → ритми → стан у git.
> Джерело: дослідження «Godot-інді студія з ШІ-командою» (2026-11-05, https://claude.ai/artifact/J5kSt6HmHX7qqDGx8FhB28; правила R1–R12, режими відмови F1–F9) + уроки цього репо (F10–F11, `.claude/skills/gamedev`).
> Ревізія: 2026-11-05. Змінюй цей файл лише PR-ом типу `process` з підставою.

## Для власника — три дії

| Ти | Агент робить сам |
|---|---|
| **Кажеш, чого хочеш**, звичайними словами: «хочу бачити, звідки йде робот» | маршрут через `/gamedev` → стовп → спека → код → тести від вимог → кадри + тест Ніколая → вердикт воріт → PR із доказами |
| **Тиснеш кнопку**, коли агент питає (або кажеш «вирішимо») | збирає всі відкриті рішення, дає варіанти з рекомендацією, записує вибір у файли (`/decide`) |
| **Мерджиш PR** (або пишеш «мердж») | CI перевіряє докази; агент стежить за CI і править сам |

Хочеш сигнал від живих людей — скажи «плейтест»: агент дасть білд, картку задач і бланк, а після сесії ти надиктовуєш, що бачив, і він сам заповнить журнал і тріаж.

Файли процесу, ролі, журнали й звіти нижче — робота агента. Ти їх не редагуєш і не викликаєш. Решта документа — довідка «як і чому так».

## 0. Теза

**Ми виробляємо не код, а перевірений досвід гравця.** ШІ зробив виробництво дешевим; дефіцитними лишились дві речі: **судження власника** і **сигнал від живих гравців**. Тому процес оптимізує одне — *максимум сигналу на одиницю уваги власника*:

- машини відповідають на «**чи працює**» — автоматично, з доказом, без участі людини;
- люди відповідають на «**чи зручно й цікаво**» — рідко, але обов'язково і до того, як дороге (арт, контент) зроблене;
- агент **пропонує**, власник **вирішує**, і межа між цим записана, а не «зрозуміла з контексту».

Головні болі (неправильні механіки, керування, UI) **не лікуються кращою генерацією коду** — їх лікують ворота до арту й плейтести.

## 1. Принципи (P1–P10)

Кожен принцип має механізм, який його тримає. Принцип без механізму — побажання.

| # | Принцип | Чому | Механізм |
|---|---|---|---|
| **P1** | **Рішення ≠ виконання.** Ядро, стовпи, scope, модель вводу, баланс, політика ШІ-арту — лише власник. | Агент ухвалює сотні дрібних дизайн-рішень у коді й нагромаджує обсяг (F4, F5). | Реєстр `docs/design/decisions.md` (OD-n); PR-гейт PR-6: зміна правил гри без REQ/OD/spec — блок. |
| **P2** | **Без доказу нема «готово».** | «Виглядає робочим» ≠ працює (R2). | Розділ «Докази» у PR; PR-гейт PR-4/PR-5 (кадр для видимого). |
| **P3** | **Відчуття — людям, працездатність — машинам.** | ШІ виміряє дугу стрибка, але не скаже, що вона «пливе» (R7). | Ворота G0, G5, G6 завжди людські; агент не пише «цікаво». |
| **P4** | **Дешеве спершу.** Ідея < спека < грейбокс < код < арт < контент. | Переробка готового арту/контенту — найдорожча помилка (R5). | Арт (`/gen-art`) лише для механік, що пройшли G0–G1. |
| **P5** | **Детермінізм = відтворюваність = діагностованість.** | Баг, який не відтворюється, не лагодиться; агенту потрібен стан текстом (R3, Luden.io). | Seeded RNG, `world_hash`, twin-тести; fix несе seed/регресію (PR-7). |
| **P6** | **Малий вхід, малий вихід.** Одна історія = один видимий результат = один PR. | Фіча «під ключ» непередбачувана (F4); великий диф не рев'юється. | PR-гейт PR-9 (> 800 рядків продукту); історії з REQ-ID. |
| **P7** | **Нічого без стовпа.** Фіча, що не підсилює стовп, — «заморожено», не «пізніше». | Нагромадження scope — вбивця інді (F5, R10). | Поле «Стовп» у PR (PR-3); `docs/design/scope.md`. |
| **P8** | **Незалежне око.** Автор ≠ перевіряльник; тест пишуть від спеки, не від коду. | Тести того самого агента сліпі до його припущень (F3); мультиагентний peer-review без виходу — театр (F7). | Агенти `qa-adversary` (тести від REQ), `fresh-eyes` (тест Ніколая без контексту), `integrity` (вердикти воріт без права правити). |
| **P9** | **Віднімання ≥ додавання.** Кожна фіча щось прибирає: з HUD, з контексту, з коду. | UI і контекст ростуть лише додаванням (F6, F10). | Розділ «Що прибрано» у PR; бюджет HUD ≤ 16 елементів; поріг AGENTS.md 40 КБ у звіті. |
| **P10** | **Вимірюй процес, не лише гру.** | Без метрики процес дрейфує в ритуал. | `docs/process/rework-log.md` → `npm run process` каже, які ворота посилити; LLM Week раз на квартал. |

## 2. Цикл поставки

```
 Інтент власника
   │  (1) /gamedev: тріаж → маршрут
   ▼
 Стовп? ──ні──► питання власнику (OD-n) або «заморожено» у scope.md
   │так
   ▼
 Спека specs/NNNN (REQ-ID, анкета механіки, що прибирає)      ← designer
   │  (2) рев'ю дизайну за реєстром D/M (game-design.md)        ← integrity
   ▼
 G0 грейбокс: керування без арту, відгук ≤ 100 мс              ← developer + ВЛАСНИК пробує
   ▼
 Історії (1 PR = 1 видимий результат): код + тести + докази     ← developer
   │  тести від REQ, не від коду                                 ← qa-adversary
   │  кадр → тест Ніколая (G3)                                  ← fresh-eyes
   ▼
 PR-гейт (CI: інтент · стовп · докази · підстава) → вердикт воріт ← integrity
   ▼
 Батч плейтесту (G5, 3–7 людей мовчки) → правки того ж дня       ← ВЛАСНИК
   ▼
 Арт/контент (/gen-art) → демо-тест (G6)                          ← незалежний тестер
```

**Ворота G0–G6** (визначення й пороги — `.claude/skills/gamedev/SKILL.md` §5–§8): G0 прототип керування · G1 ядро і стовпи · G2 матриця вводу · G3 UI-аудит + тест Ніколая · G4 перші 60 с (FTUE) · G5 людський плейтест · G6 демо як тест.

### Definition of Ready (історію можна брати)
- є підстава: `REQ-NNNN-n` у спеці **або** `OD-n` (рішення власника) **або** це `fix`/`refactor`/`process`;
- названо стовп (S1–S3) або `infra`/`process`;
- названо, **як доведемо**: який тест, кадр, хеш або метрика FTUE;
- влазить в один PR з одним видимим результатом.

### Definition of Done (історію можна закрити)
- `npm test` + `npm run lint` + Godot-сьюти (`test.cmd` / CI) зелені, без ObjectDB-ліків;
- докази в PR: лог; для видимого — кадр до/після (`newhud shot …`); для правил — `world_hash`/twin;
- тексти, які стали неправдою, оновлені в тому ж PR (анкета §4 п.6, F10);
- «Що прибрано» заповнено (або чесне «нічого — бо …»);
- для видимого — тест Ніколая пройдено або відкриті проблеми записані;
- PR-гейт зелений; правка власника після мерджу → рядок у `rework-log.md`.

## 3. Ролі

Мінімальний набір (lean): чотири ролі + незалежне око. Кожна має **перевірюваний вихід** і **заборону**. Роль без виходу — театр (F7). Визначення агентів — `.claude/agents/`.

| Роль | Агент | Вхід | Вихід (перевірюваний) | Не має права |
|---|---|---|---|---|
| **Власник** | — | вердикти, плейтести | рішення OD-n, стовпи, scope, вердикт G0/G5 | — |
| ШІ-геймдизайнер | `designer` | інтент, стовпи, реєстр D/M | спека з REQ-ID, анкета, варіанти для OD | змінювати стовпи, scope, числа балансу |
| ШІ-розробник | `developer` (або основна сесія) | історія з REQ/OD | код + тести + докази у PR | змінювати правила гри мимохідь; закривати без доказу |
| PM-цілісність | `integrity` | усі артефакти | таблиця вердиктів G0–G6 + блокери + питання власнику | писати код чи правила (інструменти лише читання) |
| QA-противник | `qa-adversary` | REQ-ID спеки | тести/сценарії, що атакують припущення | правити продуктовий код |
| Незалежне око | `fresh-eyes` | лише кадри | топ-5 проблем розуміння (тест Ніколая) | читати код, спеки, контекст проєкту |

**Маршрутизація моделей** (CCGS-патерн): дешева — читати, форматувати, тріаж логів; основна — реалізація; найсильніша — синтез кількох документів, рев'ю дизайну, вердикти воріт. Вибір моделі агента — налаштування власника (`model:` у frontmatter), за замовчуванням успадковується.

## 4. Ритми

| Каденс | Що | Хто | Артефакт |
|---|---|---|---|

| Щотижня | батч-плейтест 3–7 людей + розбір rework-log | власник | `docs/process/playtests/YYYY-MM-DD-*.md` |

| Механізм | Де | Тримає |

| PR-гейт (інтент · тип · стовп · докази · кадр · підстава) | `.github/workflows/process.yml` → `tools/process/check-pr.mjs` | P1, P2, P6, P7 |

- Неоднозначну відповідь власника читати «на гірше» (видаляти зроблене) — перепитай або продовжуй (F11).

## 8. Як змінювати процес

Процес — теж продукт. Зміна = PR типу `process` з **підставою** (рядок rework-log, провал воріт, результат LLM Week) і **доказом** (тест тулінгу, звіт до/після). Принцип, що не має механізму, або механізм, що не ловить нічого три місяці, — кандидат на видалення (P9).
