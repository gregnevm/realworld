# decide — рішення власника без редагування файлів

Власник не редагує markdown. Він натискає кнопку, а агент пише у файли (P1: вирішує власник, виконує агент).

## Кроки
1. `npm run process` → відкриті OD, статус стовпів, рядки scope без вердикту.
2. Порядок: спершу те, що блокує роботу: OD-1 (стовпи) → OD-3 (scope) → OD-2 (ввід) → решта за номером.
3. На кожне питання дай 2–4 варіанти:
   - перший варіант — рекомендація агента з позначкою «(Рекомендовано)» і однією фразою «чому»;
   - в описі кожного варіанта — **що зміниться в роботі** після вибору;
   - «Інше» додається автоматично — туди власник пише своє;
   - стовпи: показуй сам текст ядра й стовпів в описі, а не посилання на файл;
   - scope: не по рядку на систему, а пакетом («прийняти пропозицію агента» / «жорсткіше» / «нічого не морозити»).
4. `AskUserQuestion`: ≤ 4 питання за виклик. Кожне самодостатнє, бо власник може не бачити попередніх повідомлень.
5. Запиши відповіді:
   - `docs/design/decisions.md`: `open` → `decided`, сьогоднішня дата, вибір дослівно в «Варіанти / вибір»;
   - `docs/design/pillars.md`: `Статус: **approved**` (і правки тексту), якщо OD-1 вирішено;
   - `docs/design/scope.md`: колонка «Вердикт власника» за вибором;
   - нове питання, що виникло з відповіді, — новий рядок OD зі статусом `open`.
6. `npm test` (файли стану мусять парситись) → коміт → PR (`Тип: docs`, `Стовп: process`, підстава — OD-n).
7. Відповідь власнику — одна таблиця «рішення → що тепер зміниться в роботі агента».

## Не роби
- Не вирішуй за власника, навіть коли варіант очевидний: лише рекомендуй.
- «Пізніше» або без відповіді — OD лишається `open`. Не тисни.
- Не питай про те, що вже `decided`.
