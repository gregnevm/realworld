# godot-game-uiux-designer

Скіл для RealWorld (`godot/`, Godot 4.7, GDScript, UI українською). Дистильовано з реальної роботи: кожне правило нижче вже коштувало помилки або дало видимий виграш на скриншоті.

## 0. Принципи
1. **Спершу дивись, потім правь.** Кожен цикл = кадр «до» → зміна → кадр «після». Рішення без скриншота не приймаються. Дивись на **кадр цілком**, а не на шматок, який щойно змінив: найбільші провали (голий спавн-екран, шов-сітка тайлів) ховались у тому, що не оглядали.
2. **Порівнюй із реальними іграми**, а не з попередньою версією. Питання кожного циклу: «що в RimWorld / Factorio / Dwarf Fortress (Steam) / Kenshi тут виглядало б краще і чому?»
3. **Цикл = аудит → ранжуй проблеми за візуальним впливом → 1–3 найбільші → перевір → коміт.** Не роби «усе потроху».
4. **Анімація обов'язкова** (без неї гра «неграбельна»), але лише view-only: годинник стіни/дифи чисел сима; ніколи запис у сим і RNG.
5. **Шукай нове в кожному циклі** (WebSearch / `mcp__Parallel_Search__web_fetch`) і дописуй у §9.
6. **Не ламай контракти:** R1–R12 (`AGENTS.md`), тести зелені, `.import`/`newhud_thumb.png` не комітити, ключ не друкувати. Не інтерпретуй відповідь користувача «на найгірше»: при двозначності («з таким результатом краще не створюй») перепитай або продовжуй цикл, а не видаляй зроблене.

## 1. Інструментарій (все в репо)
```bash
tools/ux/shots.sh <godot> <out>                 # desktop.png, touch.png, spawn.png + value-звіт
godot --path godot res://newhud.tscn -- newhud shot [light|spawn|death|gear|fx] [touch scale=1.68]
python3 -I tools/ux/value_check.py shot.png gray.png   # тест «обезбарви»: mean/std/p5/p95
for s in parse_check run_ui_tests run_tests run_smoke; do godot --headless --path godot -s res://tests/$s.gd | grep -E "RESULT|FAIL|SCRIPT ERROR"; done
npm test && npm run lint                         # маніфест арту синхронний, secret-scan
```
Godot: CI-бінарник `Godot_v4.7-stable_linux.x86_64` (zip із GitHub-релізу), скриншоти під `xvfb-run -a -s "-screen 0 1600x720x24"`.
Режими `shot`: без аргументів = те, що бачить гравець (**без** оверлею L); `light` вмикає оверлей світла (CI-демо); `spawn`/`death`/`gear`/`fx` показують відповідний екран/панель/текст.

## 2. Цикл (повторюй, поки кадр не витримає порівняння з референсом)
```
1 кадр «до» (desktop + touch + spawn/death) → 2 жорсткий аудит → 3 референси/статті (нова практика)
4 арт через gen-art (якщо чогось бракує) → 5 код → 6 тести → 7 кадр «після» → 8 коміт/пуш/журнал
```
Приймається, якщо: тести/лінт зелені, `git status` без `.import`, кадр не гірший на всіх кадрах.

## 3. Аудит-чеклист (по всій грі, не по шматку)
- **Перша хвилина:** спавн-екран має арт, назву, атмосферу? (Голий список кнопок = провал першого враження.) Екран смерті має вагу й причину?
- **Мапа:** сіра версія читається? Об'єкти відділені від тла (контур, тінь, яскравість)? Видно повтор/шви тайлів? Є берегова лінія, а не різкий шов?
- **Жива сцена:** дихає (ідл), рухається (хода), реагує (удар), має ефекти (вогонь, вітер), дає числа (+N / −N)?
- **HUD:** частка екрана під HUD (ціль ≤ 25%), dev-дані перед гравцем (сховати), щільність (скільки одночасно на екрані?), ієрархія (що головне?), іконки арту чи емодзі, панелі «важкі» чи «скляні», чи є що сховати (прогресивне розкриття)?
- **Touch:** цілі ≥ 44–48 px, мапа ≥ 60 % висоти, фід не перекриває будбар?
- **Фідбек:** hover/press, поява повідомлень, дублікати складаються?

## 4. Практики, перевірені тут (з джерелами)
- **Value plan.** Сцена має читатись у сірому; земля — малий розкид яскравості, об'єкти й актори — найсвітліші/найконтрастніші; надто багато контрасту скрізь = нічого не виділяється. [Reducing Visual Confusion](https://icewyrmgames.github.io/research/reducing-visual-confusion-in-your-game). Реалізація: `GROUND_TINT` + `GROUND_FLATTEN` (стиснуте тло) + темний контур спрайтів (`OUTLINE`, 4 зсуви) + контактна еліптична тінь.
- **Тайли.** Баланс ваги всередині тайла, мало кольорів, жорсткий контраст = шум; читабельність сцени важливіша за тайл. [Pixelblog 20](https://www.slynyrd.com/blog/2019/8/27/pixelblog-20-top-down-tiles). Реалізація: flip (4 варіанти) + ±4 % jitter із хеша клітинки; берегова лінія (піна на суші, мокра кромка на воді).
- **HUD.** Прогресивне розкриття (3–5 головних, решта за контекстом), edge-індикатори загроз, тач-цілі ≥ 44–48 dp. Реалізація: клік по заголовку панелі згортає тіло (`_install_fold`), довга другорядна панель стартує згорнутою.
- **Тултіпи Factorio (FFF #318).** Живий стан сутності, структура, без нерелевантного.
- **Godot UI.** Контейнери володіють розкладкою; стилі через `Theme`; hover/press — Tween ~0.1 с ease-out, новий твін глушить попередній; UI під `Control/CanvasLayer`.
- **Анімація.** Ease-out для появи (200–300 мс), squash/stretch у точці удару, ідл-дихання ≈2 %, `ease-out-cubic` fade+pop для нових повідомлень; juice підсилює механіку, не формула.
- **Меню.** Повноекранний key-art + градієнтний скрім під текстом + повільний zoom-цикл (≈26 с) + поетапна поява елементів (70 мс/елемент) — меню ніколи не статична картинка.

## 4а. Мокапи UI дорожчою моделлю
Для пошуку напряму: прямий виклик `generateContent` моделі `gemini-3-pro-image` (ключ із `.env.local`, ніколи не друкувати), опис ГРИ абстрактно (світ, герой, механіки, платформа) + 3 різні формулювання запиту «найкращий HUD» × 2 варіанти, `aspectRatio: 16:9`. Не описувати поточний UI — інакше модель його копіює. Збіг у більшості варіантів = сильний сигнал; кращі — у `docs/ux/refs/`.

## 5. Арт-конвеєр (gen-art)
- Ключ: `printf %s '<KEY>' | node tools/gen-art.mjs key` (пише `.env.local`, ключ у виводі маскувати: `sed 's/AQ\.[A-Za-z0-9_-]*/AQ.***/g'`).
- Види: `ui` (64, keyed), `icon`/`sprite`/`actor` (128, keyed), `tile` (64, безшовний), **`key` (16:9, без keying/resize — фон екранів)**. Нові рядки руками: `manual: true` у `art/manifest.json`, потім **`node tools/gen-art.mjs sync`** (інакше `npm test` падає на «manifest in sync»).
- **Єдина рамка набору:** якщо частина іконок у кружку/плиті, а частина «голі» — набір не консистентний. У `notes` усім: `bare object only: NO frame, NO roundel, NO badge, NO plate; single bold silhouette filling the frame, strong dark outline, no text`.
- Цикл: `gen --kind <k> --limit 12 --n 2|3` → композит кандидатів на тлі трави (Pillow) → Read → `approve <id>@vN` → невдалі перегенеруй з `notes` + `--force`. Для `key` дивись, де порожня темна зона під текст (зліва знизу).
- Підключення: `ui/art_icons.gd` (`ArtIcons.res/ui/for_glyph/building/key/texture`) і `world_view.art_texture`. Двошляхове завантаження (ResourceLoader → `Image.load_from_file`) обов'язкове — headless/свіжий checkout без import-кешу. Відсутній PNG = емодзі/вектор-фолбек, ніколи порожнє місце. Емодзі панелей мапляться на арт через `GLYPH_ART` (панелі не змінюються).
- Спрайти мають ~20 % прозорих полів → завжди малюй/показуй по `get_used_rect()` (`content_rect`, `AtlasTexture`).
- Пін-тест: `_t_art_icons` (кожен `GLYPH_ART` → реальний PNG).

## 6. Анімація в RealWorld (усе view-only)
| Що | Де |
|---|---|
| Дихання, хода-боб + нахил, удар-сквош, замах роботи | `world_view._draw_actor` (`_gait_of` = фаза за пройденою відстанню) |
| Вітер на деревах/кущах (фаза за клітинкою), мерехтіння+гало вогню/ламп | `_draw_node`, `_draw_building` (`LIGHT_KINDS`) |
| Спливаючі `+N` (з іконкою ресурсу) / `−N` | `world_view.observe_sim` + `_draw_fx` (дифить числа сима; тест `_t_world_fx`) |
| Потреби: ease-заповнення, пульс у `crit` | `Widgets.NeedBar._process` |
| Hover/press будбару й меню | `BuildBarPanel._pop`, `Chrome.pop_button` |
| Поява повідомлень, склейка «×N» | `FeedWidget._rebind` / `_on_feed` |
| Меню: фон-zoom, stagger, смерть fade 1.2 с | `lifecycle.gd` `Chrome` |
Pivot — підніжжя/центр; `draw_set_transform_matrix` завжди скидати.

## 7. ГОЧІ, що коштували часу
- **Negative rect size у `draw_texture_rect` НІЧОГО не малює** (чорні клітинки в шаховому порядку). Віддзеркалення тільки через `draw_set_transform_matrix` зі scale −1 навколо pivot.
- Dev-режим скриншота вмикав оверлей світла — діагональні штрихи по всій мапі «виглядали як баг гри». Дефолтний кадр має бути тим, що бачить гравець; оверлеї — окремими аргументами.
- Inner class не бачить `static func` зовнішнього файлу без префікса: хелпери виносити в `class Chrome` і викликати `Chrome.xxx`.
- Підклас уже мав `_body` → конфлікт імен із базою: префіксуй (`_fold_body`).
- Після збільшення відступів панелей фід налазив на док → перерахуй `MAX_H` і дивись кадр.
- Сирий `ColorRect`/`Color(` у `ui/` заборонені R3 → кольори тільки `Tokens.*` / `Tokens.with_alpha`.
- Ворог у `sim.enemies` — Dictionary (немає `get_instance_id`): ключ анімації = індекс.
- `godot --import` та `shot` лишають `*.png.import` і `godot/newhud_thumb.png` → не комітити; Stop-hook вимагає чистого дерева — видаляй (`tools/ux/shots.sh` робить це сам).
- `git push --force` заборонений; `--force-with-lease` лише для гілки з уже змердженою історією. Після squash-мерджу гілку стартуй від `origin/main`.
- `WebFetch` на закритих хостах = `ENOTFOUND` → не ретраїти, брати `mcp__Parallel_Search__web_fetch`.
- `:=` не виводить тип із Variant; кожен `var` типізований (tripwire у `run_tests`).

## 9. Журнал циклів (нові зверху)
**Прохід 3 — мобільний редизайн (після «прибери шкали»).** Метод, що спрацював: (1) глибоке дослідження першоджерел агентом (Google 48dp/≥8dp зазор, Apple 44pt/текст 17pt, GAG «не лише колір»/контраст, The Long Dark — радіальні статуси, Don't Starve — бейджі з пульсом ≤33%, Stardew — «числа там, де вони змінюють рішення», Clash of Clans — ресурси вгорі праворуч, «піп лише за реальної причини»); (2) **мокапи дорожчою моделлю за АБСТРАКТНИМ описом гри** (`gemini-3-pro-image`, 3 промпти × 2 варіанти, без опису поточного UI) — усі 6 зійшлися на медальйонах замість шкал; (3) реалізація: `Medallion`, `bare`-панелі, будбар лише іконками, ціль-чип. Уроки: шкали потреб — антипатерн для мобільного HUD; у нормі потреба = тьмяна іконка, число й колір — лише коли значення змінює рішення; рефери-мокапи зберігати в `docs/ux/refs/`.
**Прохід 2 (5 циклів, після «ужасно виглядає»).** Діагноз: HUD ~45% екрана, dev-дані перед гравцем (режисер, англ. теги), дефолтний шрифт, мапа без відгуку на наказ. (1) HUD-дієта: склад-сітка, режисер за хоткеєм, без тегів, фід 3/10 с, вужчі доки. (2) Типографіка: Rubik + Oswald, контраст MUT/DIM до AA. (3) Мапа: плавна камера, шлях + ціль, хвиля, кільце героя, віньєтка. (4) Juice: поп будівлі, тремтіння ноди, пуф, тряска, поява панелей. (5) Онбординг: пульс слота цілі; touch-фід над будбаром. Уроки: **перше питання аудиту — «скільки екрана займає HUD і що з нього гравцю не потрібно»**; dev-дані в HUD = миттєвий «прототип»-вайб; шрифт — найдешевший великий виграш; кожен наказ потребує видимого підтвердження (кільце/шлях); онбординг показує на контрол, а не лише описує його.
**Цикл 4 — спорядження + згортання.** Іконки `item_*` у GearPanel; `_install_fold` (клік по заголовку), Research стартує згорнутим. Проблема: гортана ліва колонка ховала Gear. Практика: прогресивне розкриття.
**Цикл 3 — відгук і скло.** `Theme._sb_glass` (прозорість, світла кромка, тінь), фід не перекриває док, спливаючі `+N/−N`. Практика: скляні панелі над світом, числа як відгук.
**Цикл 2 — перше враження.** Key-art `key_spawn`/`key_death` (новий kind `key`), скрім, zoom-цикл, stagger, картки пресетів; `shot spawn/death`. Практика: меню — це сцена, а не список.
**Цикл 1 — мапа.** Варіація тайлів + берег, фікс negative-rect, віддзеркалення через матрицю, `shot` без L-оверлею. Раніше: арт у `world_view`, обрізка полів, тіні, контури, value plan, зум 1.5; HUD-іконки (10 `ui_*`), будбар зі спрайтами, hover-твіни, ease NeedBar, touch-фід.
**Наступні кандидати:** день/ніч-палітра (теплий/холодний градінг), погода-частинки (сніг/дощ) як шар, діегетичний стан героя (поза/колір при низьких потребах), edge-індикатори загроз, звук-відгук, GearPanel/Research у більш компактній формі, екран дослідження як дерево, мінікарта.
