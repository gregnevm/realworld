# Специфікація: Інвентар та екіпірування персонажа

> Цикл: Specify → Plan → Tasks → Implement. Заповни Specify повністю перед реалізацією — агент виконає більше автономно й точніше.
> Статус: done (Godot) · Дата: 2026-06-30 · Спринт: 1

## 1. Specify
- **Мета (навіщо):** поглибити симуляцію єдиного персонажа (стовп «Одне життя, глибока симуляція») — додати предмети та екіпіровані інструмент/зброю, що відчутно впливають на видобуток і бій. Це робить прогресію персонажа відчутною без колонії пешок.
- **Проблема зараз:** персонаж має лише `carry` (мішок ресурсів) і фіксовані параметри. Прогресія — тільки скіли (`skills.gather/combat`). Немає предметів, екіпіровки, причини крафтити спорядження.
- **Не-цілі (out of scope):** дерево досліджень; броня зі слотами по частинах тіла; торгівля предметами через конвої; деградація/ремонт інструменту (окрема ітерація).
- **Обмеження:** vanilla JS, no-build, неймспейс `RW`, classic scripts; логіку тримати **DOM-free** (тестовно в Node); зберігати зворотну сумісність save-формату (міграція старих збережень без падіння).
- **Критерії прийняття:**
  - [ ] Є таблиця предметів `RW.ITEMS` (id, name, slot: `tool|weapon`, ефекти: множник швидкості видобутку та/або бонус урону).
  - [ ] Верстак може крафтити щонайменше 2 предмети (напр. `сокира` з дерева+каменю, `спис` з дерева+брухту) як `bill`.
  - [ ] Екіпірований інструмент пришвидшує `gather` (перевірюваний множник), зброя збільшує урон melee.
  - [ ] Чиста функція `RW.gatherTime(node, player)` і `RW.meleeDamage(player)` інкапсулюють розрахунок і покриті тестами.
  - [ ] Старі збереження (без предметів) завантажуються без помилок (поля з дефолтами).
  - [ ] UI: мінімальна панель екіпіровки (показ поточних tool/weapon) — не блокує критерії вище.
- **Файли/модулі в скоупі:** `game/js/entities.js` (таблиця ITEMS + крафт-рецепти), `game/js/game.js` (екіпіровка, gatherTime/meleeDamage, save/load-міграція), `game/js/ui.js` (панель екіпіровки), `tests/sim.test.js` (нові кейси). Без змін у `worldgen/render/input` без потреби.

## 4. Implement
Реалізовано в **Godot-порті** (`godot/`) — Godot тепер форвард-движок; веб-JS лишається референс-прототипом.
- `data.gd`: `ITEMS` (axe/pick — tool; club/spear — weapon) + `ITEM_ORDER` + рецепти.
- `sim.gd`: `player.equipped {tool, weapon}` + `player.items`; чисті `gather_time(node)` і `melee_damage()` (єдине джерело істини, читають екіпіровку); `craft_item(id)` (потрібен верстак → платить рецепт → авто-екіп) + `equip(id)`; підключено в `_do_gather` / `_do_attack`.
- `main.gd`: панель спорядження (клавіша **I**) з крафтом/екіпіруванням + індикатор екіпіровки в HUD.
- Тести: `_t_items` (8 кейсів) — крафт без верстака падає; axe/spear крафтяться й авто-екіпіруються; інструмент пришвидшує видобуток; зброя підсилює урон; невідомий предмет відхиляється. **35 unit + 8 smoke — зелено** (локально + CI).

Відхилення: деградація/ремонт інструменту — поза скоупом (як і планувалось); реалізовано в Godot, не JS (свідомо); save-міграція н/д (Godot-порт ще без save).
